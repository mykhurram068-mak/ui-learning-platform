JavaScript Array Methods

Every method you need — map, filter, reduce, find, and 20+ more. Each with a link to the full reference page, when to use it, and whether it mutates.

Last updated: October 2026 • Reading time: ~15 minutes

Quick answer: Use map() to transform every element, filter() to keep some elements, reduce() to collapse an array into one value, find() to get the first match, and forEach() to loop without building a new array.

🎯 The 5 methods you'll use daily

If you learn nothing else, learn these. They cover 90% of real array work.

Method Returns Use when Mutates?
map() New array, same length Transform every element No
filter() New array, shorter or equal Keep only matching elements No
reduce() Any single value Collapse into sum, count, object No
find() Element or undefined Get the first match No
forEach() undefined Side effects only (log, save) No

The most important distinction:

map(), filter(), and reduce() return new values. forEach() returns nothing — it's for side effects.

If you've ever written const x = arr.forEach(...) and gotten undefined, that's why.

🔄 Transform methods

Change each element and get a new array back. Non-destructive.

map() Safe
Transform every element. Returns a new array of the same length. The most-used array method.
flatMap() Safe
Map then flatten one level. Faster than map().flat(). Use when your map returns arrays.
flat() Safe
Flatten nested arrays. Specify depth or use Infinity for complete flattening.
concat() Safe
Merge two or more arrays into a new array. Non-destructive alternative to push.
slice() Safe
Copy a portion of an array. Supports negative indices. Never mutates.

🔍 Filter methods

Remove elements that don't match a test. Returns a new array.

filter() Safe
Keep only elements that pass a test. Returns a new array (possibly empty).
find() Safe
Return the first element that matches. Returns undefined if none do. Short-circuits.
findIndex() Safe
Return the index of the first match, or -1. Perfect for updates and removals.
some() Safe
Return true if any element passes a test. Short-circuits on first match.
every() Safe
Return true if all elements pass a test. Short-circuits on first failure.
includes() Safe
Check if an array contains a value. NaN-safe. Returns boolean.

📉 Aggregate methods

Collapse an array into a single value. The Swiss Army knife of array methods.

reduce() Powerful
Collapse an array into anything — sum, count, grouped object, string. The most flexible method.
reduceRight() Powerful
Same as reduce but iterates right-to-left. Rarely needed but useful for string reversal.
join() Safe
Convert an array to a string with a separator. Default comma.

🔁 Iterate methods

Loop over elements for side effects. No new array returned.

forEach() Safe
Run a function on every element. Returns undefined. Cannot be broken out of early.

➕ Add and remove methods

These methods mutate the original array. Use with intention.

push() Mutates
Add one or more elements to the end. Returns the new length.
pop() Mutates
Remove and return the last element. Fastest removal. O(1).
shift() Mutates
Remove and return the first element. Re-indexes the rest. O(n).
unshift() Mutates
Add one or more elements to the start. Returns the new length. O(n).
splice() Mutates
Add, remove, or replace elements at any position. Returns removed elements.
sort() Mutates
Sort elements in place. Always pass a comparator for numbers.
reverse() Mutates
Reverse the array in place. Returns the same array reference.

✨ Create methods

Build a new array from scratch or from an iterable.

Array.from() Safe
Create an array from any iterable or array-like object.
Array.fromAsync() ES2026
Create an array from an async iterable. Returns a Promise. New in ES2026.
Array.of() Safe
Create an array from arguments. Fixes the Array(3) quirk.
at() Safe
Return the element at an index. Supports negative indices for the nth-from-end item. ES2022.

⚖️ map vs filter vs reduce — the one question everyone asks

The most-searched comparison. Here's the definitive answer.

M

map() — transform every element

Use when you want to change each element and keep the same array length.

const prices = [10, 20, 30];
const withTax = prices.map(p => p * 1.1);
// [11, 22, 33]

If your output array is the same length as the input, you probably want map.

F

filter() — keep some elements

Use when you want to remove elements that don't match a condition.

const prices = [10, 20, 30];
const expensive = prices.filter(p => p > 15);
// [20, 30]

If your output array is shorter than the input, you probably want filter.

R

reduce() — collapse to one value

Use when you want to combine all elements into a single value.

const prices = [10, 20, 30];
const total = prices.reduce((sum, p) => sum + p, 0);
// 60

// Group by category
const grouped = items.reduce((acc, item) => {
  acc[item.category] = acc[item.category] || [];
  acc[item.category].push(item);
  return acc;
}, {});

If you're not getting an array back, or the answer is a number/object, you probably want reduce.

Chaining them together:

// Get total price of items over $50, with tax
const total = items
  .filter(item => item.price > 50)
  .map(item => item.price * 1.1)
  .reduce((sum, price) => sum + price, 0);

This is the pattern. filter → narrow down, map → transform, reduce → sum up.

🛡️ Mutating vs non-mutating — the complete list

Memorize this. It prevents 90% of array bugs.

Mutates the original array

  • push(), pop()
  • shift(), unshift()
  • splice()
  • sort(), reverse()
  • fill(), copyWithin()

Returns new array

  • map(), filter()
  • slice(), concat()
  • flat(), flatMap()
  • toReversed(), toSorted(), toSpliced()

ES2023+ added non-mutating versions: toReversed(), toSorted(), and toSpliced() work exactly like their mutating siblings but return new arrays. If you're writing React or Vue code, always use these instead of reverse(), sort(), or splice().

⚠️ Common mistakes to avoid

  • Using forEach when you need a result. forEach returns undefined. Use map if you want a new array.
  • Forgetting the initial value in reduce. Without it, an empty array throws an error.
  • Sorting numbers without a comparator. [10, 9].sort() returns [10, 9], not [9, 10].
  • Assuming slice and splice are the same. slice returns a copy; splice mutates.
  • Using push in React state. Always use spread: setItems([...items, newItem]).
  • Chaining filter after map when filter would be faster first. Filter first, then map — fewer items to process.
  • Using forEach when you need early exit. You can't break out of forEach. Use a for...of loop or find.

❓ Frequently asked questions

What is the difference between map and filter in JavaScript?

map transforms every element and returns a new array of the same length. filter keeps only the elements that pass a test and returns a shorter array. Use map to change items, filter to remove items.

What is the difference between forEach and map?

forEach runs a function on each element for side effects and returns undefined. map returns a new array with transformed elements. Use forEach when you don't need the result, map when you do.

When should I use reduce instead of map or filter?

Use reduce when you need to collapse an array into a single value — a sum, a count, a grouped object, a string. map and filter return arrays; reduce returns anything.

What is the difference between find and filter?

find returns the first matching element or undefined. filter returns a new array with all matches. Use find when you need one item, filter when you need all.

What is the difference between slice and splice?

slice returns a new array copy without modifying the original. splice mutates the original array by removing, replacing, or inserting elements.

Which array methods mutate the original array?

push, pop, shift, unshift, splice, sort, reverse, fill, and copyWithin mutate. map, filter, reduce, find, findIndex, slice, concat, flat, flatMap, and includes do not.
