How to update an array in state.
Add, remove, edit, sort — no mutation.

Arrays are the most common collection in React state — to-do lists, chat messages, search results. Every update must produce a new array, not mutate the old one. The methods you already know (push, splice, sort) are exactly the ones you can't use. This page covers every array operation with the immutable pattern.

Short answer: Use methods that return new arrays: filter (remove), map (update), spread (add), slice / spread (copy). Never use push, splice, sort, reverse — they mutate. For sorting, copy first: [...items].sort(). Always use the functional setter: setItems(prev => ...). When in doubt: setItems(prev => produceNewArray(prev)).

✅ Solution 1 — Add, remove, update

The three operations you'll use most.

Each operation has one right pattern. Adding uses spread. Removing uses filter. Updating uses map. All three return a new array — React sees the new reference, re-renders. The old array stays untouched, which is exactly what React needs.

Add = spread

[...prev, item] — new array, item at end. [item, ...prev] for beginning.

Remove = filter

prev.filter(i => i.id !== id) — new array without matching items. Never splice.

Update = map

prev.map(i => i.id === id ? {...i, done: !i.done} : i) — new array, item updated, others preserved.

Never mutate

push, splice, sort, reverse — all mutate. React sees the same reference, no re-render.

Memorize four methods: filter, map, spread, slice. They cover every array update. filter removes. map transforms. Spread adds. slice copies. Every array operation you'll ever need is built on these four. Push, splice, sort — the mutating methods — you'll never call on state. Once you internalize the four immutable methods, array updates become mechanical.

✅ Solution 2 — Sort, reverse, and other mutating methods

Copy first, then mutate the copy.

Some array methods only come in mutating form — sort, reverse, splice. You still need them. The fix: copy the array with spread, then call the method on the copy. The original stays untouched; the sorted/reversed result is a new array.

interface Item {

setItems(prev =>

setItems(prev =>
[...prev].sort((a, b) => a.price - b.price)
);

setItems(prev => [
...prev.slice(0, index),
item,
...prev.slice(index)
]);
}

...prev.slice(0, index),

Copy before sort

[...prev].sort() — new array, sorted. Without spread, sort mutates state.

ES2023 immutable methods

toSorted, toReversed, toSpliced — return new arrays. Use them when targeting modern JS.

Slice for insert/remove

[...prev.slice(0, i), item, ...prev.slice(i)] — insert. Without the middle item — remove.

Sort on render instead

If the sort is derived, keep state unsorted. const sorted = [...items].sort(...) during render.

sort mutates in place — this is the #1 array bug. Even experience React developers hit it. items.sort() reorders the original array, then setItems(items) passes the same reference — React sees no change, no re-render. The items appear unsorted even though sort ran. Fix: setItems([...items].sort()) — one spread fixes it. Same for reverse, splice, push, pop, shift, unshift. If the method's name doesn't start with "to" or "slice" or "map" or "filter", it probably mutates.

✅ Solution 3 — Advanced patterns

Nested objects, multiple updates, and reducers.

Real array updates often involve nested objects — updating items[3].tags, or removing items[3].metadata.author. The spread pattern extends to every level. For complex sequences of updates, useReducer is cleaner than multiple setters.

Nested: spread every level

{'{...item, metadata: {...item.metadata, tags: [...]}}'} — copy the item, copy its metadata, update the tags.

useReducer for many updates

Add, remove, update, clear — each is one action. One reducer handles them all with consistent patterns.

Derive, don't store

Sorted, filtered, total — compute during render. Storing them causes sync bugs.

The complete toolkit

filter, map, spread, slice for updates. useReducer for multiple related operations. useMemo for expensive derivations.

⚠️ Common mistakes

The array update bugs that cost real time.

1. Using push on state

items.push(x); setItems(items) — same reference. Fix: setItems([...items, x]).

2. Using splice on state

items.splice(i, 1) — mutates. Fix: items.filter((_, idx) => idx !== i).

3. Using sort on state directly

items.sort() — mutates. Fix: [...items].sort() or items.toSorted().

4. Mutating array elements

items[0].done = true — mutates. Fix: items.map(i => i.id === id ? {...i, done: true} : i).

5. Forgetting functional setter

setItems([...items, x]) uses stale items if called twice fast. Fix: setItems(prev => [...prev, x]).

6. Assigning new array to same variable

items = [...items, x]; setItems(items) — works but confusing. Fix: setItems(prev => [...prev, x]).

7. Using index as key in a mutable list

After sort/reorder, index keys cause state leaks. Fix: key={item.id} — stable identity.

8. Storing derived arrays

sortedItems in state, synced with useEffect. Fix: compute during render.

❓ Frequently asked

How do I add an item to an array in React state?

Use the spread operator: setItems([...items, newItem]) or, with the functional form, setItems(prev => [...prev, newItem]). This creates a new array with the new item appended. Never use items.push(newItem).

How do I remove an item from an array in state?

Use filter: setItems(prev => prev.filter(i => i.id !== id)). Filter returns a new array without the matching items. Never use splice — it mutates.

How do I update an item in an array in state?

Use map: setItems(prev => prev.map(i => i.id === id ? { ...i, name: 'new' } : i)). Map iterates, returns a new object for the matching item, leaves others unchanged.

How do I sort an array in state?

Sort mutates the original array, so never call it on state directly. Copy first: setItems(prev => [...prev].sort((a, b) => a.name.localeCompare(b.name))). Same for reverse.
