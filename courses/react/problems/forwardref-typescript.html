"Property 'focus' does not exist on type 'never'."
Three causes, three fixes.

The forwardRef type error that stumps every TypeScript + React project the first time. You wrapped your component in forwardRef, passed a ref from the parent — and the compiler says the ref is never, or that focus doesn't exist. Both are the same bug: forwardRef's generics weren't supplied, so the ref type collapsed. This page covers the three causes, the three fixes, and the correct typing for forwardRef + useImperativeHandle.

Short answer: Pass both generics. forwardRef((props, ref) => ...). The first generic is the ref's target — a DOM element type or a custom handle interface. The second is the props type. Without generics, ref is never. For useImperativeHandle, pass the handle interface as the generic to both. In React 19, prefer ref as a regular prop — forwardRef is no longer required.

✅ Solution 1 — No generics on forwardRef

The most common cause: forwardRef((props, ref) => ...) with no type parameters.

Without generics, forwardRef defaults its ref type to unknown, and React's ref utilities narrow it to never. The compiler can't know what element the ref attaches to, so it can't check access. Fix: supply both generics — element type first, props type second.

no-generics.tsx 
import { forwardRef, useRef } from 'react';

// ─── BAD: no generics ────────────────────────
const BadInput = forwardRef((props, ref) => {
// ❌ ref is typed never — no .current, no .focus()
// ❌ TS: Property 'focus' does not exist on type 'never'
// ❌ props is {} — no name, no placeholder
return ;
});

// ─── GOOD 1: both generics ───────────────────
interface InputProps {
placeholder?: string;
name: string;
}

const GoodInput = forwardRef((props, ref) => {
// ✅ ref is Ref — .current is HTMLInputElement | null
// ✅ props is InputProps — name and placeholder autocomplete
return ;
});

// ─── GOOD 2: element-only generic ────────────
// When the component takes no props, only the ref type is needed
const BareInput = forwardRef((props, ref) => {
// ✅ ref is Ref — props is {}
return ;
});

// ─── GOOD 3: parent call sites ───────────────
function Parent() {
const inputRef = useRef(null);

// ✅ ref type matches — no cast, no error
return (







);
}

// ─── Naming the component ────────────────────
// forwardRef loses the function name — set displayName for DevTools
// and for React's error messages. Not a type error, but a lint error
// under react/display-name.
GoodInput.displayName = 'GoodInput';
BareInput.displayName = 'BareInput';

Two generics

forwardRef. First is the ref target, second is props. Missing either loses inference.

never = missing generic

Without the first generic, ref is unknown narrowed to never. Any access fails.

Element type

HTMLInputElement, HTMLButtonElement, HTMLDivElement — match the element the ref attaches to.

displayName

forwardRef loses the function name. Set Component.displayName = 'Component' for DevTools and lint.

✅ Solution 2 — Wrong ref type

The generic must match the element — or the handle you expose.

The first generic is the ref's target. If you pass the wrong type — HTMLButtonElement for an input, or HTMLElement when you need HTMLInputElement — the ref doesn't match the element, and access fails. Fix: match the element, or use useImperativeHandle to expose a custom handle.

wrong-ref-type.tsx 
import { forwardRef, useImperativeHandle, useRef } from 'react';

// ─── BAD: wrong element type ─────────────────
const BadInput = forwardRef((props, ref) => {
// ❌ ref is Ref but attached to an input
// ❌ TS: Type 'Ref' is not assignable to 'Ref'
return ;
});

// ─── BAD: too-broad element type ──────────────
const BroadInput = forwardRef((props, ref) => {
// ❌ HTMLElement has no .value, no .focus with input semantics
// ❌ TS: Property 'value' does not exist on type 'HTMLElement'
return as React.Ref} {...props} />;
});

// ─── GOOD 1: match the element ───────────────
const GoodInput = forwardRef((props, ref) => {
// ✅ ref is Ref — .value, .focus all work
return ;
});

// ─── GOOD 2: useImperativeHandle for custom API ──
interface InputHandle {
focus(): void;
clear(): void;
getValue(): string;
}

const CustomInput = forwardRef((props, ref) => {
const inputRef = useRef(null);

// ✅ Expose a custom handle instead of the raw DOM node
// The handle type flows from parent → forwardRef → here
useImperativeHandle(ref, () => ({
focus() {
inputRef.current?.focus();
},
clear() {
if (inputRef.current) inputRef.current.value = '';
},
getValue() {
return inputRef.current?.value ?? '';
}
}), []);

return ;
});

✅ Solution 3 — React 19's ref-as-prop

forwardRef is no longer required. ref is a regular prop.

In React 19, function components can accept ref directly in props. No forwardRef wrapper, no extra generics — just a normal prop of type Ref. Existing forwardRef code still works, but new code should prefer the prop. It's simpler and TypeScript infers correctly.

ref-as-prop.tsx 
import { Ref, useImperativeHandle, useRef } from 'react';

// ─── React 19: ref as a prop ─────────────────
interface InputProps {
name: string;
ref?: Ref; // regular prop
}

function Input({ name, ref }: InputProps) {
// ✅ No forwardRef wrapper — ref is just a prop
// ✅ TypeScript infers Ref from the interface
return ;
}

// ─── Custom handle with ref-as-prop ──────────
interface InputHandle {
focus(): void;
clear(): void;
}

interface CustomProps {

},

ref as a prop

React 19 accepts ref in the props object. No forwardRef wrapper needed for new code.

Ref type

Type the prop as ref?: Ref. It accepts both callback and object refs.

No displayName

The prop form keeps the function name. DevTools shows Input without extra setup.

forwardRef still works

React 19 supports both. Migrate only when you touch the component — no forced rewrite.

Don't skip the generics to "make it work." forwardRef((props, ref) => ...) compiles — with ref: never and props: {}. It silently disables every ref check and every prop check for that component. The bug shows up later as a runtime Cannot read property 'focus' of null, or as a prop typo that nobody caught. The two generics are not optional polish — they're the only thing making forwardRef type-safe.

⚠️ Common mistakes

The type errors that cost real time.

1. No generics on forwardRef

forwardRef((props, ref) => ...) — ref is never. Fix: forwardRef.

2. Only the props generic

forwardRef — that's the ref generic, not props. Fix: both in order, ref first.

3. Wrong element type

forwardRef on an . Fix: match the element.

4. Over-broad HTMLElement

Loses .value, .checked. Fix: the specific element type.

5. Forgetting displayName

Lint error under react/display-name. Fix: Component.displayName = 'Component'.

6. useImperativeHandle generic mismatch

The handle interface must match between forwardRef, useImperativeHandle, and the parent's useRef. Break one link and the type collapses.

7. Casting ref as any

Silences the error, loses all safety. Fix: the correct generic.

8. Using forwardRef in new React 19 code

Not wrong, but unnecessary. Fix: accept ref as a prop and type it as Ref.

❓ Frequently asked

How do I type forwardRef in TypeScript?

Three causes, three fixes. (1) No generics — forwardRef defaults to unknown and ref is typed never. Fix: pass both type parameters: forwardRef((props, ref) => ...). (2) Wrong ref type — the first generic must match the element or handle you expose. (3) Missing displayName — not a type error, but a lint error. Always pass both generics, and make ref the second parameter.

Why does my ref have type 'never' in forwardRef?

Because forwardRef's first generic defaults to unknown, and React's ref utilities narrow it. Without the generic, the compiler can't know what element the ref attaches to, so it infers never. Fix: forwardRef((props, ref) => ...). The first generic is the ref's target type. The second is the props type. Both are required for good inference.

What is the difference between forwardRef and ref-as-prop in React 19?

In React 18 and earlier, forwardRef was the only way to pass a ref to a function component. In React 19, ref is a regular prop — you can accept it directly in the props object. forwardRef is still supported for compatibility but is no longer required. For new code on React 19, prefer ref as a prop: function Input({ ref, ...props }: InputProps & { ref?: Ref }). It's simpler and removes the extra wrapper.

How do I type useImperativeHandle?

Define a handle interface with the methods you expose, then pass it as the second generic to forwardRef, and as the generic to useImperativeHandle. For example: interface InputHandle { focus(): void; clear(): void }, forwardRef((props, ref) => { useImperativeHandle(ref, () => ({ focus() { inputRef.current?.focus(); }, clear() { ... } })); }). The handle type flows from the parent's useRef(null) through forwardRef to useImperativeHandle. Break any link and the type collapses to never.
