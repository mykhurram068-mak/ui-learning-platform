"Type is not assignable to type 'IntrinsicAttributes & Props'."
Three causes, three fixes.

The prop error every TypeScript + React project hits the first week. You passed a prop, TypeScript rejected it — and the message mentions IntrinsicAttributes, which sounds like React internals, not your code. It's not. The compiler is telling you exactly which prop it doesn't recognize, and why. This page covers the three causes, the three fixes, and the correct shape of a props interface.

Short answer: Declare a Props interface, one field per prop, correct type. Pass it to the component function. function Card({ title, count }: CardProps) {'{ ... }'}. The three causes: (1) the prop isn't in the interface, (2) the prop is there but the value has the wrong type, (3) the component has no props interface at all. Fix each at the interface — never with any.

✅ Solution 1 — Prop missing from the interface

The most common cause: you passed a prop the interface doesn't declare.

The interface lists some props. You pass one more. TypeScript rejects it — the extra prop isn't in the type. Fix: add the prop to the interface, or remove it from the call site. The error message names the prop exactly: Property 'subtitle' does not exist on type 'CardProps'.

React.createElement('h2', null, title),
subtitle && React.createElement('p', null, subtitle)

function DynamicCard({ title, ...rest }) {
return React.createElement('div', { 'data-rest': JSON.stringify(rest) }, title);
}

One field per prop

Every prop the component accepts must be declared in the interface. No field → rejected at the call site.

Optional with ?

subtitle?: string — the prop may or may not be passed. Without ?, it's required.

extends for shared props

interface CardProps extends BaseProps — inherit className, id, etc. from a shared type.

Index signature

[key: string]: unknown — allows any extra prop. Use sparingly — it disables the check.

✅ Solution 2 — Wrong prop type

The prop is declared, but the value you passed doesn't match the type.

The interface has the prop, but you passed a string where it expects a number, or an object where it expects a string. The error names both types: Type 'string' is not assignable to type 'number'. Fix: change the value, or change the declared type. Never cast to any to silence it.

// BAD: value doesn't match the declared type
interface BadBadgeProps {
count: number;
label: string;
}

function BadBadge({ count, label }: BadBadgeProps) {
return (

return (

{String(label)}: {String(count)}

);
}

// GOOD 3: accept a broader type, narrow inside

label: string;

{label}: {count}

);

function FlexibleBadge({ count, label }) {
return React.createElement('span', null, String(label), ': ', String(count));
}

function Badge({ count, label, onClick }) {
return React.createElement('span', { onClick }, label, ': ', count);
}

function CorrectApp() {
return React.createElement('div', null,
React.createElement(Badge, { count: 5, label: 'Items' }),
React.createElement(Badge, {
count: 0,
label: 'Empty',

})
);
}

export { App, CorrectApp, FlexibleBadge };

Read the error

Type 'X' is not assignable to type 'Y' — X is what you passed, Y is what the interface expects. Fix one of them.

Union types

count: number | string — accept both. Good when the value comes from user input or an API.

Function props

onClick?: (e: React.MouseEvent) => void — optional callback, typed parameter.

No any

count={'{5 as any}'} silences the error but removes the check. Fix the type or the value.

✅ Solution 3 — No props interface at all

The component has no props type — TypeScript defaults to IntrinsicAttributes.

When a component has no props interface, TypeScript uses React's built-in IntrinsicAttributes, which contains only React internals (key, ref). Every custom prop you pass is rejected. Fix: declare a props interface — even an empty one if the component takes no props.

Always declare Props

Even interface Props {'{}'} for prop-less components. Without it, TypeScript defaults to IntrinsicAttributes.

Destructure the props

function Greeting({ name }: GreetingProps) — destructure in the signature, type the whole object.

React.FC

Older style, still supported. Less preferred than a plain function, but works. Use it if your team prefers it.

Prop-less component

function Divider(_props: DividerProps) {'{ ... }'} — takes no props. The interface is empty but exists.

Don't cast props to any to silence the error. {'{ name: "Alice" } as any'} compiles, but the next refactor breaks it silently. Every prop check is gone for that component. The right fix is to declare the prop in the interface — one field, correct type. It's the same amount of typing, and it keeps the compiler doing its job.

⚠️ Common mistakes

The prop errors that cost real time.

1. Prop not in the interface

You passed a prop the interface doesn't declare. Fix: add it to the interface, or remove it from the call site.

2. Wrong value type

The prop exists but the value doesn't match. Fix: check the error, fix the value or the declared type.

3. No props interface at all

TypeScript defaults to IntrinsicAttributes — every custom prop rejected. Fix: declare a Props interface.

4. Confusing ? optional with default

subtitle?: string means "may be undefined" — not "has a default". Fix: add a default in destructuring.

5. Forwarding props through a wrapper

The wrapper doesn't accept the prop, so it can't pass it through. Fix: add the prop to the wrapper's interface and forward it.

6. Using React.FC and missing the generic

React.FC with no type parameter is React.FC<{}> — no custom props. Fix: React.FC.

7. Casting to any

Silences the error, removes the check. Fix: declare the prop correctly.

8. Index signature everywhere

[key: string]: unknown allows any prop — disables the check entirely. Fix: declare each prop explicitly.

❓ Frequently asked

How do I fix "Type is not assignable to type IntrinsicAttributes & Props" in React?

Three causes, three fixes. (1) Missing prop — you forgot to declare a prop in the interface, or you passed a prop the interface doesn't have. Fix: add the prop to the interface, or use the correct name. (2) Wrong prop type — the value you passed doesn't match the declared type. Fix: check the error carefully; it usually names the exact prop and the exact type mismatch. (3) Component has no props interface — TypeScript defaults to IntrinsicAttributes, which has no custom props. Fix: declare a Props interface.

What is IntrinsicAttributes in React?

IntrinsicAttributes is React's base type for all JSX attributes. It contains only the internal key and ref props. When your component has no explicit props interface, TypeScript defaults to IntrinsicAttributes, which means any custom prop you pass is rejected. Fix: declare a Props interface with the fields you need. Then IntrinsicAttributes & Props is the actual type, and your custom props are accepted alongside the built-in ones.

Why does my component reject a prop I'm clearly passing?

Three reasons. (1) The prop isn't in the interface — add it. (2) The prop is in the interface but the value is the wrong type — check the value's type. (3) You're passing the prop to a wrapper component that doesn't forward it — the wrapper needs to accept and pass the prop through. Read the full error: TypeScript names both the prop and the type mismatch. Fix the specific prop, not the whole interface.

Should I use interface or type for React props?

Both work. Interface supports declaration merging and is the convention in many React codebases. Type is fine for simple cases and can be slightly stricter. Pick one and be consistent. The compiler treats them identically for React props. The only functional difference is that interface can be extended with declaration merging, while type cannot.
