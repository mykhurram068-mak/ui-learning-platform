"A React component suspended while rendering, but no fallback UI was specified."
Three causes, three fixes.

The Suspense error that hits every project the first time you reach for React.lazy. A lazy component rendered without a Suspense ancestor throws — React has nowhere to show the loading state, so it fails loudly. This page covers the three causes (missing boundary, boundary in the wrong place, failed import), the three fixes, and the correct pattern for route-level code splitting.

Short answer: Every lazy component needs a Suspense ancestor with a fallback. Put the boundary above the lazy component in the tree — and inside the router, not around it. The three causes: (1) no Suspense boundary, (2) boundary outside the router, (3) the lazy import fails (wrong path, no default export). Fix each at the boundary. Never lazy-load without a fallback — React will throw instead of rendering nothing.

✅ Solution 1 — No Suspense boundary

The most common cause: a lazy component rendered without a Suspense ancestor.

A lazy component suspends while its module loads. React looks up the tree for the nearest Suspense boundary. If there is none, it throws: A React component suspended while rendering, but no fallback UI was specified. Fix: wrap the lazy component (or a parent) in Suspense with a fallback prop.

Every lazy needs Suspense

React.lazy suspends. The nearest Suspense shows the fallback. No boundary, no render — it throws.

Boundary above the lazy

The Suspense ancestor must be in the same tree, higher up. Siblings or children won't catch it.

One boundary for many

A single Suspense around multiple lazy components shows one fallback until all are loaded.

Fallback is required

The fallback prop is the UI shown while suspended. It's not optional — omitting it causes the error.

✅ Solution 2 — Suspense boundary in the wrong place

The boundary exists, but it's above the router or on the wrong branch.

You wrapped the app in Suspense, but the lazy route is rendered by the router — and the router is a sibling of the boundary, not a descendant. Or the boundary is inside the route element, which hasn't been created yet when the route suspends. Fix: put the boundary inside the router, around the routes — not around the router itself.

Boundary inside the Router

Suspense around Routes, not around BrowserRouter. The route element is the lazy one.

Per-route boundaries

Wrap each route's element in its own Suspense. Each page has its own loading state.

Layout with Outlet

A Layout component wraps the Outlet in Suspense. One fallback for the whole route group.

Data routers

React Router's data router API (createBrowserRouter) may need the boundary inside the element or via HydrateFallback.

✅ Solution 3 — The lazy import fails

The module fails to load — wrong path, no default export, or a network error.

A lazy import must resolve to a module with a default export. If the path is wrong, the module doesn't exist, or it exports only named exports, the loader fails — React either suspends forever (no error boundary) or throws Element type is invalid. Fix: verify the path, add a default export, or re-map the module in the loader. Add an error boundary for production resilience.

lazy-import-fails.tsx 
import { lazy, Suspense } from 'react';
import { ErrorBoundary } from 'react-error-boundary';

// BAD 1: wrong path — the module doesn't exist
const BadPath = lazy(() => import('./does-not-exist'));

// BAD 2: module has no default export
// The loader resolves, but the module has only named exports.
// React.lazy expects { default: Component }.
const BadNamedExport = lazy(() => import('./NamedOnly'));

// GOOD 1: fix the path
const GoodPath = lazy(() => import('./pages/About'));

// GOOD 2: map a named export to default at the loader
const GoodNamedExport = lazy(() =>
import('./NamedOnly').then((module) => ({
default: module.NamedComponent,
}))
);

// GOOD 3: add an error boundary for real network failures
function App() {
return (
Something went wrong loading the page.
}>
Loading…
}>




);
}

// GOOD 4: retry the import once on failure
const RetryLazy = lazy(() => {
return new Promise<{ default: React.ComponentType }>((resolve, reject) => {
import('./pages/About')
.then((module) => resolve({ default: module.default }))
.catch(() => {
// Retry once — useful for transient network failures
import('./pages/About')
.then((module) => resolve({ default: module.default }))
.catch(reject);
});
});
});

Default export required

The loader must resolve to {'{ default: Component }'}. Named exports alone fail with Element type is invalid.

Map named to default

.then(m => ({'{ default: m.Named }'})) — re-map the named export at the loader, no module change needed.

Error boundary

Catch network failures. Without one, a rejected lazy load throws to the nearest error boundary or crashes the app.

Retry logic

Wrap the import in a promise that retries once on failure. Useful for flaky networks and CDN cache misses.

Don't lazy-load without a fallback — and don't skip the error boundary. A lazy component that never resolves (network failure, wrong path) suspends forever if there's no Suspense fallback. With a Suspense fallback but no error boundary, the app hangs at the fallback. With neither, React throws. The right pattern is always: ErrorBoundary → Suspense fallback → LazyComponent. Treat this as a stack, not a single component.

⚠️ Common mistakes

The lazy + Suspense errors that cost real time.

1. No Suspense boundary

{''} rendered without a Suspense ancestor. Fix: wrap it (or a parent) in Suspense.

2. Suspense around the Router

The boundary is outside the tree that contains the lazy element. Fix: put it inside the Router, around the routes.

3. No default export

export const Comp = ... — the loader resolves to {'{ Comp }'}, not {'{ default: Comp }'}. Fix: add a default export, or map named to default in the loader.

4. Wrong import path

The module doesn't exist. Fix: check the path. Vite and Webpack both fail loudly here, but the error is at runtime.

5. Missing error boundary

Network failure hangs at the fallback forever. Fix: wrap in an error boundary with a reset.

6. Lazy-loading small components

The extra request costs more than the bundle size saved. Fix: lazy-load routes and heavy features, not tiny components.

7. Using import() inside the component

The import runs on every render. Fix: lazy(() => import(...)) at module scope.

8. Forgetting HydrateFallback in data routers

React Router's data router API needs HydrateFallback for SSR. Fix: provide it at the route level.

❓ Frequently asked

How do I fix "A React component suspended while rendering, but no fallback UI was specified"?

Three causes, three fixes. (1) A lazy component is rendered outside any Suspense boundary. Fix: wrap it (or its parent) in Suspense with a fallback. (2) The Suspense boundary is above the Router, so the lazy route has no ancestor boundary. Fix: put Suspense inside the route element, not around the Router. (3) The lazy import failed — network error, wrong path — and React suspended forever. Fix: use an error boundary, or ensure the module path resolves.

Why does React.lazy say "not a function"?

Two common causes. (1) You imported it incorrectly — React.lazy is a named export of the React package, not a method on the default export in all setups. Fix: import { lazy } from 'react' or React.lazy. (2) You're on an older React version that predates lazy (React 16.6+ has it). Check your version. In React 19, lazy is still available as React.lazy and as a named import. The error almost always means the import is wrong, not that the function doesn't exist.

How do I code-split routes with React.lazy?;

Wrap each route element in lazy, then put Suspense around the routes (inside the Router, above the Routes). The dynamic import returns a module with a default export — the component must be exported as default. For React Router v6+, use the element prop with Suspense around the lazy element, or wrap the entire Routes in one Suspense — the fallback shows for the first navigation only.

Does React.lazy work with named exports?

No — React.lazy expects a module with a default export. Named exports fail with "Element type is invalid". Two fixes: (1) add a default export to the module: export default MyComponent. (2) Re-export at the import site: React.lazy(() => import('./Comp').then(m => ({ default: m.NamedExport }))). The second is useful when you don't own the module or don't want to change it.
