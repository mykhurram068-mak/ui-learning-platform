"Generic type 'Component' requires 1 type argument(s)."
Three causes, three fixes.

The generic component error that hits every TypeScript + React project the first time you try to write a typed list. The compiler either parses your type parameter as JSX, or can't infer it from the props, or you forgot to declare it at all. This page covers the three causes, the three fixes, and the correct syntax for generic components in .tsx.

Short answer: Put the generic on the function, not the props interface. Write function List(props: Props). In .tsx, arrow functions need a trailing comma: const List = (props) => .... The generic must appear in a prop field so JSX can infer it — items: T[] works, a generic return type doesn't. The three causes: (1) TSX parses the generic as JSX, (2) no type parameter on the component, (3) the generic isn't inferable at the call site.

✅ Solution 1 — TSX parses the generic as JSX

The most common cause: arrow function with a bare generic in a .tsx file.

In .tsx, an opening angle bracket at the start of an expression is parsed as a JSX element. Fix: add a trailing comma after the generic, or use a function declaration.

Trailing comma

In .tsx, a bare generic is JSX. Add a trailing comma after the type parameter to disambiguate.

Function declaration

function List(props) — unambiguous in both .ts and .tsx. No comma needed.

Generic on the function

Not on the props interface. ListProps is the props type; belongs to the component.

React.FC has no generics

Use a function declaration or a typed function alias. React.FC can't express a generic component.

✅ Solution 2 — No type parameter on the component

The props reference the generic, but the function never declares it.

You wrote the props type with a generic, but the function signature has no type parameter. Fix: declare the type parameter on the function, before the props parameter.
