"Generic type 'Component' requires 1 type argument(s)."
Three causes, three fixes.

The generic component error that hits every TypeScript + React project the first time you try to write . The compiler either parses your as JSX, or can't infer the generic from the props, or you forgot to declare the type parameter at all. This page covers the three causes, the three fixes, and the correct syntax for generic components in .tsx.

Short answer: Put the generic on the function, not the props interface. function List(props: Props) {'{ ... }'}. In .tsx, arrow functions need a trailing comma: const List = (props) => .... The generic must appear in a prop field so JSX can infer it — items: T[] works, a generic return type doesn't. The three causes: (1) TSX parses as JSX, (2) no type parameter on the component, (3) the generic isn't inferable at the call site. Fix each at the declaration.

✅ Solution 1 — TSX parses as JSX

The most common cause: arrow function with a bare generic in a .tsx file.

In .tsx, at the start of an expression is parsed as a JSX element — the compiler expects a tag name and attributes, not a type parameter. The error is usually "JSX element 'T' has no corresponding closing tag" or "Type 'T' is not a valid JSX element". Fix: add a trailing comma after the generic — — or use a function declaration, which is unambiguous.

trailing comma

In .tsx, is JSX. is a type parameter. One character fixes the parse.

Function declaration

function List(props) — unambiguous in both .ts and .tsx. No comma needed.

Generic on the function

Not on the props interface. ListProps is the props type; belongs to the component.

React.FC has no generics

Use a function declaration or a typed function alias. React.FC can't express a generic component.
