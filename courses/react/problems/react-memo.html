React · memo re-render

Home › Courses › React › Problems › React.memo
⚛️ Problem · 6 min read

"I wrapped it in React.memo. It still re-renders."
Three causes, three fixes.

React.memo is the most misunderstood performance tool in React. It does a shallow comparison — not a deep one — and any new prop reference defeats it. Objects, arrays, and functions created in the parent's render are new references on every render. This page covers the three causes, the three fixes, and the mental model that makes memoization predictable.

Short answer: React.memo compares props with Object.is. A new reference re-renders. The three causes: (1) a new object or array prop, (2) a new function prop, (3) new children elements. Fix: use useMemo for objects/arrays, useCallback for functions, and lift children out or pass props instead. Don't memo every component — it's a trade-off, not a default.

✅ Solution 1 — New object or array prop

The most common cause: an object or array created inline in the parent.

Every render creates new objects and arrays. React.memo compares with Object.is, so two objects with identical contents are still different references. Fix: hoist the value out of the render, or wrap it in useMemo so the reference stays stable across renders.

Shallow comparison

React.memo uses Object.is per prop. Two equal objects are different references. One new prop defeats memo.

Hoist static values

If the object never changes, define it outside the component. Same reference every render, no useMemo needed.

useMemo for dependencies

When the object depends on state, wrap it in useMemo with the correct deps. New reference only when deps change.

Primitives are stable

theme="dark", size={12} — passed by value, compared by value. No new reference.

✅ Solution 2 — New function prop

Functions are objects. An inline handler is a new reference every render.

Every render creates a new closure for an inline handler. React.memo sees a new function reference and re-renders the child. Fix: wrap the handler in useCallback. The dependency array keeps the reference stable until a real dependency changes.

Functions are objects

An inline arrow is a new function value on every render. React.memo treats it as a different prop.

useCallback

Memoize the function itself. Same reference until a dependency changes. Include every captured value in the deps.

Module-scope handlers

If a handler doesn't close over state, define it outside the component. Same reference forever, no hook needed.

Don't useCallback without memo

If the child isn't wrapped in React.memo, useCallback does nothing. The child re-renders anyway.

✅ Solution 3 — New children elements

Children are React elements. New JSX is a new element — new reference.

The most subtle case. When you pass JSX as children, React creates a new element on every render. React.memo sees a new reference and re-renders. Fix: pass props instead of children, or lift the children out of the parent's render, or accept that this particular prop defeats memo (and memoize differently).

Children are elements

JSX in the parent creates a new React element every render. That's a new reference for children.

Pass data, not JSX

Instead of

Title

, pass title="Title" and render the h2 inside.

Hoist static children

If the children never change, define them outside the component. Same element reference, memo works.

Split and memoize

Wrapper always renders — fine. Memoize the expensive inner part. The wrapper is cheap; the child is skipped.

Don't wrap every component in React.memo. React.memo has a cost: the shallow comparison on every render, plus the extra reference tracking in the parent (useCallback, useMemo, hoisted objects). For cheap components, the comparison costs more than the render. Use React.memo when the component is expensive (large lists, charts, complex trees) or renders frequently from an unrelated parent. Measure before memoizing.

⚠️ Common mistakes

The memoization errors that cost real time.

1. Inline object prop

{''} — new object every render. Fix: hoist or useMemo.

2. Inline function prop

{' ...} />'} — new function every render. Fix: useCallback or hoist.

3. Inline array prop

{''} — new array every render. Fix: hoist or useMemo.

4. New children elements

JSX passed as children is a new element every render. Fix: pass data as props, hoist children, or split and memoize.

5. Using useCallback without React.memo

If the child isn't memoized, useCallback does nothing. Fix: memo the child, or skip the hook.

6. Missing dependency in useCallback

A stale closure or a new reference on every dep change. Fix: include every captured value in the deps array.

7. Deep comparison assumption

React.memo is shallow. Two equal objects are still different references. Fix: stabilize the reference, or pass a custom compare.

8. Memoizing every component

The comparison costs more than cheap renders. Fix: memo only expensive or frequently rendered components.

❓ Frequently asked

Why is my React.memo component still re-rendering?

Three causes, three fixes. (1) A new object or array is passed as a prop on every render — React.memo does a shallow comparison, so a new reference defeats it. Fix: lift the value out of render, or useMemo it. (2) A new function is passed as a prop — functions are objects, and a new closure is a new reference. Fix: wrap the handler in useCallback. (3) The parent passes children or inline JSX — children is a new element every render. Fix: move the children outside the memoized component, or pass props instead. React.memo is a shallow comparison; every prop must be the same reference between renders to skip.

Does React.memo do a deep comparison?

No — React.memo does a shallow comparison by default. It compares each prop with Object.is. If every prop is the same reference, it skips the re-render. If a single prop is a new object, array, or function, it re-renders. You can pass a custom compare function as the second argument to React.memo to do a deeper comparison, but the default is shallow. Most memoization bugs come from assuming it's deep.

When should I use useCallback with React.memo?;

Use useCallback whenever a function prop is passed to a memoized child. A function defined inline in the parent is a new reference on every render, so the memoized child re-renders. Wrap it in useCallback with the correct dependency array. If the function captures no changing values, the dependency array is empty. If it captures state or props, include them. Do not use useCallback without React.memo on the child — it's wasted work.

Is React.memo always worth it?

No. React.memo has a cost: the shallow comparison on every render, plus the extra reference tracking you have to maintain (useCallback, useMemo, stable references). For components that render quickly, the comparison costs more than the render. Use React.memo for components that are expensive to render (large lists, heavy charts) or that render frequently. Don't wrap every component by default.
