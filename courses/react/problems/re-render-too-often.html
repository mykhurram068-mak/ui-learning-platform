"My component re-renders too often."
Three causes, three fixes.

React re-renders are not a bug by default — they're the rendering model. But when a single keystroke cascades through the whole tree, or a context change re-renders every consumer, that's a design problem, not a performance one. This page covers the three structural causes, the three fixes, and the rule for where state belongs.

Short answer: React re-renders a component when its state, its parent, or its context changes. The three causes: (1) state placed too high in the tree, (2) a context value that's a new object every render, (3) a parent that re-renders on every event. Fix each by moving state down, memoizing the context value, and extracting the expensive child. Don't reach for React.memo first — fix the structure.

✅ Solution 1 — State placed too high

The most common cause: state lives in a parent that doesn't need it.

When state lives high in the tree, every change re-renders the entire subtree — even children that don't read the state. Fix: move the state down to the component that actually needs it. If only one child uses it, the state belongs there. The parent stops re-rendering on every change.

State at the lowest consumer

Put state in the component that reads it, not the component that owns the subtree. Move it down.

Lift only when shared

Two siblings need the same value? Lift to their common parent. One component? Keep it local.

Extract consumers

When state must stay high, extract the parts that read it. Static siblings render once.

Measure, don't guess

React DevTools Profiler shows which components rendered. Find the actual cascade before refactoring.

✅ Solution 2 — Context value is a new object every render

The provider creates a new value object, and every consumer re-renders.

Context compares its value with Object.is, just like React.memo compares props. If the provider passes a new object literal on every render, every consumer re-renders — even those that only read a field that didn't change. Fix: wrap the context value in useMemo, or split the context into stable and volatile parts.

context-new-object.tsx 
import { createContext, useContext, useMemo, useState } from 'react';

interface AppContextValue {
user: string;
theme: string;
count: number;
}

const AppContext = createContext(null);

// BAD: new value object every render — every consumer re-renders
function BadProvider({ children }: { children: React.ReactNode }) {

const [user] = useState('Alice');
const [theme] = useState('dark');

return (


{children}

);
}

function UserBadge() {
const ctx = useContext(AppContext);
console.log('UserBadge rendered');
return {ctx?.user};
}

// GOOD 1: memoize the context value

const [user] = useState('Alice');
const [theme] = useState('dark');

() => ({ user, theme, count }),

{children}

const CountContext = createContext(0);

Context compares by reference

The provider's value is compared with Object.is. A new object literal re-renders every consumer.

useMemo the value

Wrap the context value in useMemo. Same reference unless a dependency actually changed.

Split the context

Separate rarely-changing from frequently-changing data. Consumers of the rare one stop re-rendering on every change.

Extract consumers

Move the component that reads the volatile field into its own component. Siblings don't re-render.

✅ Solution 3 — Parent re-renders on every event

A state change at the top cascades through the whole tree.

The parent owns state that changes on every keystroke or scroll. React re-renders the parent — and by default, every child, whether or not its props changed. Fix: extract the expensive child into its own component, memoize it if props are stable, or move the state into a sibling that doesn't share the cascade.

Default re-render

Every child re-renders when the parent re-renders. Only React.memo skips it (with stable props).

Extract the input

Move the state and the input into a child. The parent doesn't re-render on every keystroke.

Memo the expensive child

If the parent must re-render, memo the heavy child. It skips when props are the same reference.

Stable children trick

Pass JSX as children from a stable parent. The element reference is stable — the wrapper skips the render.

Don't reach for React.memo before fixing the structure. Most "too many re-renders" problems are state placement problems. Moving state down, splitting the context, or extracting a component fixes the cascade at its source. React.memo only hides the symptom — and it costs a comparison on every render. Measure with React DevTools Profiler first, then fix the structure, then memoize only what's actually expensive.

⚠️ Common mistakes

The patterns that cause cascading re-renders.

1. State placed at the root

Every keystroke re-renders the whole tree. Fix: move state to the component that reads it.

2. Context value is a new object

Every consumer re-renders on every provider render. Fix: useMemo the value.

3. One context for everything

Stable and volatile data in one context re-renders all consumers. Fix: split the context.

4. Inline object or function prop

New references on every render defeat child memoization. Fix: useMemo / useCallback / hoist.

5. Memoizing the wrong thing

Memoizing a cheap child costs more than it saves. Fix: measure first, memoize expensive components.

6. Reading state in the parent's JSX

The parent re-renders to pass it down. Fix: pass the setter and let the child read its own state.

7. Children created inline in a memoized wrapper

New element every render. Fix: pass stable children, or don't rely on memo for the wrapper.

8. Using useReducer to avoid re-renders

The reducer doesn't prevent re-renders — it only organizes state updates. Fix: state placement.

❓ Frequently asked

Why is my React component re-rendering too often?

Three causes, three fixes. (1) State is placed too high in the tree — every change re-renders the whole subtree. Fix: move the state down to the component that actually needs it. (2) Context value is a new object every render — every consumer re-renders, even those that don't use the changed field. Fix: memoize the context value with useMemo, or split the context. (3) Parent re-renders on every keystroke — the entire tree re-renders. Fix: extract the expensive child, memo it, or move state into a sibling.

Does a React component re-render when its parent re-renders?

Yes — by default, every child re-renders when its parent re-renders, regardless of whether props changed. React.memo is the opt-out: it does a shallow prop comparison and skips the render if every prop is the same reference. Without memo, the child renders. This is why state placement matters: if state lives high, every state change cascades down

How do I stop a context from re-rendering all consumers?

Two fixes. (1) Memoize the context value — wrap the object in useMemo so its reference is stable unless a dependency changes. Without this, every render of the provider creates a new value object and every consumer re-renders. (2) Split the context — separate the rarely-changing value from the frequently-changing one. Consumers of the rare context stop re-rendering when the frequent context changes.

Should I move state down to avoid re-renders?

Usually yes. State placed in a high parent re-renders the whole subtree when it changes. If only one child needs the state, move it into that child. If several siblings need it, keep it in the parent, but extract the parts that don't need it into memoized children. Lift only when multiple components need the same value. The rule: state should live at the lowest common ancestor of the components that read it — not higher.
