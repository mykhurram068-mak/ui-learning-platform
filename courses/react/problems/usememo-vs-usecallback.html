useMemo vs useCallback.
Value vs function. Pick the right one.

Both hooks memoize. One memoizes a value; the other memoizes a function. They're the same thing under the hood — useCallback(fn, deps) is literally useMemo(() => fn, deps). But choosing between them isn't about preference; it's about what you need stable. This page shows the difference, when each matters, and when neither does.

Short answer: useMemo memoizes a value (the result of computation) — use it for expensive calculations or stable object/array identities. useCallback memoizes a function — use it for stable callback references. Both only help when the reference is consumed by something that cares (React.memo, effect dependencies, other hooks). Don't wrap everything — memoization has cost. Use it deliberately, not by default.

✅ Solution 1 — The one-line difference

Same mechanism, different return.

The simplest way to see the difference: useMemo returns the value of a function call. useCallback returns the function itself. If you need a memoized value, use useMemo. If you need a memoized function, use useCallback. They're interchangeable in principle — useCallback(fn, deps) = useMemo(() => fn, deps) — but the naming makes code clearer.

the-difference.tsx 
import { useMemo, useCallback, useState } from 'react';

function TheDifference({ items }: { items: number[] }) {
const [count, setCount] = useState(0);

// ─── useMemo: returns a VALUE ────────────────
const total = useMemo(() => {
return items.reduce((sum, n) => sum + n, 0);
}, [items]);
// total: number — the computed value

const sorted = useMemo(() => [...items].sort((a, b) => a - b), [items]);
// sorted: number[] — a new array, but stable until items changes

const user = useMemo(() => ({ name: 'Alice', age: 30 }), []);
// user: { name: string; age: number } — stable object

// ─── useCallback: returns a FUNCTION ─────────
const handleClick = useCallback(() => {
console.log('clicked');
}, []);
// handleClick: () => void — the function itself

const handleIncrement = useCallback(() => {
setCount(c => c + 1);
}, []);
// handleIncrement: () => void — stable function

// ─── Equivalent definitions ──────────────────
// These two are identical:
const cbA = useCallback(() => console.log('a'), []);
const cbB = useMemo(() => () => console.log('a'), []);
// Both return the same (() => void) function with stable identity.

// ─── The distinction in one line ─────────────
// useMemo: value = useMemo(() => compute(), deps)
// useCallback: fn = useCallback(() => { ... }, deps)
//
// Same effect. Different readability. Use the one whose
// name matches what you're returning.

console.log(total, sorted, user, handleClick, handleIncrement, cbA, cbB, count);

return (



Total: {total}


Sorted: {sorted.join(', ')}


{user.name} ({user.age})




);
}

console.log(TheDifference);

useMemo → value

const total = useMemo(() => sum(items), [items]) — total is the number, memoized until items changes.

useCallback → function

const handle = useCallback(() => ..., []) — handle is the function, memoized until deps change.

Same under the hood

useCallback(fn, deps) ≡ useMemo(() => fn, deps). Identical behavior. The name is just for clarity.

Both cache by reference

Dependencies compared by Object.is. New object/function identity → recompute. Same identity → return cached.

✅ Solution 2 — When useCallback actually helps

Only when the stable reference prevents work.

useCallback isn't a free optimization. It only helps when the stable function reference causes some other expensive thing to be skipped: a memo'd component not re-rendering, an effect not re-running, or another hook not invalidating. If nothing downstream cares about the function's identity, useCallback adds overhead with no benefit.

function useDebounce(fn: () => void, delay: number) {
useEffect(() => {

// ✅ Passing to React.memo'd component
// ✅ Used in another hook's dependency array
// ✅ Passed to a custom hook that depends on identity
//
// Don't use useCallback when:
// ❌ Passing to a native DOM event (onClick, onChange)
// ❌ Passing to a non-memo'd component
// ❌ Only used inside the component's own render logic
//
// The cost: React runs a hook + compares deps every render.
// The benefit: none, if nothing downstream compares identity.

React.memo'd children

Stable function reference = memo skips the re-render. Without useCallback, the memo is defeated by a new function identity every render.

Effect dependencies

A function in useEffect's deps — useCallback prevents re-runs from function identity changing. Without it: infinite loop.

Custom hooks

Custom hooks that depend on function identity (useDebounce, useThrottle) need stable functions. useCallback provides them.

When it's pointless

Native event handlers (onClick), non-memo'd children, internal helpers — the function is called, not compared. No benefit from memoization.

✅ Solution 3 — When useMemo actually helps

Expensive computations and stable references.

useMemo has two use cases. Expensive computation: the calculation takes real time, and skipping it on re-render matters. Stable reference: the value (object, array) is used in an effect dependency or passed to a memo'd component. For trivial computations like a + b, useMemo is slower than just recomputing.

Expensive computations

Filter + sort on 10,000 items takes real time. useMemo skips it when unrelated state changes.

Stable references

config passed to memo'd child — new object every render defeats the memo. useMemo fixes identity.

Effect dependencies

A new object in useEffect's deps causes the effect to re-run every render. useMemo prevents it.

Trivial values don't need it

a + b, items.length, user.name — no memo needed. The overhead of useMemo exceeds the computation cost.

Don't use useMemo and useCallback everywhere "just in case." Every hook has cost — React runs the hook, compares dependencies, and either caches or recomputes. For trivial values and functions, this cost exceeds the savings. The optimization is only real when the reference identity prevents work elsewhere: a memo'd child skipping a render, an effect not re-running, an expensive calculation not recomputing. Add useMemo/useCallback when you've measured a problem, not preemptively.

⚠️ Common mistakes

The memoization mistakes that cost real time.

1. Wrapping every function in useCallback

Adds cost without benefit. Fix: only memoize when the reference is consumed by something that cares.

2. Using useCallback for native events

onClick={useCallback(() => ...)} — native DOM doesn't compare identities. Fix: plain inline function.

3. Forgetting that useCallback is a hook

useCallback(...) must be called unconditionally at the top of the component. Fix: not inside loops or conditions.

4. Wrong dependencies

useCallback(() => setCount(count + 1), []) — captures stale count. Fix: setCount(c => c + 1) or add count to deps.

5. Memoizing trivial values

useMemo(() => a + b, [a, b]) — slower than a + b. Fix: only memoize when the computation actually costs.

6. Using useMemo for side effects

useMemo(() => fetch(...), []) — useMemo isn't for effects. Fix: useEffect for side effects.

7. Expecting useMemo to prevent all re-renders

useMemo memoizes the value, not the render. The component still re-renders; the value is reused. Fix: combine with React.memo to prevent child renders.

8. Not memoizing when passing to memo'd child

— new object every render, memo fails. Fix: useMemo the object or hoist it outside.

❓ Frequently asked

What is the difference between useMemo and useCallback?

useMemo memoizes a value (the result of a function call). useCallback memoizes a function (the function itself). useMemo(() => computeValue(), [deps]) returns the computed value. useCallback(() => {...}, [deps]) returns the function. They're the same thing under the hood — useCallback(fn, deps) is equivalent to useMemo(() => fn, deps).

When should I use useCallback?

Three cases. (1) A function is passed as a prop to a component wrapped in React.memo — stable reference means the memo works. (2) A function is in the dependency array of useEffect, useMemo, or another useCallback. (3) A function is passed to a custom hook that depends on it.

When should I use useMemo?

Three cases. (1) An expensive computation runs on every render but only depends on a few values. (2) A value needs a stable identity for a useEffect dependency or a memo'd component prop. (3) A value is created inline (object, array, function) and passed to a component that would re-render on the new reference.

Is useCallback always faster?

No — useCallback has cost. Every render, React runs the hook, compares dependencies, and either returns the cached function or stores a new one. For simple functions, this cost is comparable to just creating the function inline. The benefit only appears when the stable reference prevents work elsewhere.
