Setup & first component.
Three commands to running React.

Vite made React setup trivial. Three commands, sixty seconds, and you have a working React app. This lesson walks through the setup, explains JSX (the syntax that makes React readable), writes your first component, and shows you exactly how React takes that component and turns it into DOM. No webpack configuration. No create-react-app. Just the modern, simple way.

~15 minutes Beginner React 19 · Vite
React path Setup JSX First component How render works Challenge

Install React with Vite: npm create vite@latest my-app -- --template react, then cd my-app, then npm install, then npm run dev. That's it. Vite handles JSX compilation, hot reload, and bundling. Your first component is a JavaScript function that returns JSX — HTML-like syntax compiled to React.createElement calls. Modern React is 90% JavaScript, 10% JSX syntax.

Before this lesson: you must know JavaScript (functions, arrays, objects, arrow functions, destructuring). If not, complete the JavaScript track first.

⚙️ Setup — three commands

Vite is the modern standard. Faster than create-react-app, simpler than webpack.

Before you start, make sure Node.js is installed. Open a terminal and run node --version. If you see a version number (18+), you're set. If not, install Node from nodejs.org — the LTS version is fine.

Terminal 
# 1. Create a new React project
npm create vite@latest my-app -- --template react

# 2. Enter the project folder
cd my-app

# 3. Install dependencies
npm install

# 4. Start the dev server
npm run dev

 ➜ Local: http://localhost:5173/
 ➜ Network: use --host to expose

Open http://localhost:5173 in your browser. You should see the default Vite + React starter page. Change any file in src/ and the browser updates instantly — that's hot module replacement, and it's the reason Vite became the standard.

Why Vite?

create-react-app is deprecated and slow. Webpack requires 200 lines of config. Vite is fast (native ES modules in dev), zero-config, and the official recommendation from the React team.

What you get

A dev server with hot reload, JSX compilation, ES module support, and a build command. All the tooling you need for a real project, configured out of the box.

The file structure

src/ holds your components. index.html is the entry (with

). src/main.jsx is the JS entry. package.json has scripts: dev, build, preview.

Node.js version

Vite 5+ requires Node 18 or higher. Check with node --version. If you're on an older version, install the LTS from nodejs.org. Older Node versions cause cryptic errors.

Don't use create-react-app. It was the standard for years but is now officially deprecated by the React team. It's slow, uses an outdated webpack config, and hasn't been updated meaningfully. Vite is the modern answer — it's what React's own documentation now recommends. If you see a tutorial using create-react-app, it's a few years out of date.

className vs class

class is reserved in JavaScript (used for classes). JSX uses className. Same for htmlFor instead of for. These are the two most common JSX differences.

{ } — the JavaScript escape

Curly braces let you embed JavaScript in JSX. Numbers, strings, variables, function calls, ternaries — anything that evaluates to a value. {2 + 2} renders "4".

Self-closing tags

Every tag must be closed.

Inline styles

style={{ color: 'red' }} — note the double braces. The outer is the JSX expression, the inner is a JavaScript object. CSS property names are camelCase.

JSX is not HTML. It looks like it, but the rules are different. The most common errors: forgetting to close a tag (

without

Component = function

A React component is a JavaScript function that returns JSX. That's it. No class, no inheritance, no decorators. Just a function.

Capital letter

Component names start with a capital letter. App, not app. React uses the case to distinguish components from HTML tags:

is HTML, is a component.

Return JSX

The function's return value is JSX. If you return multiple elements, wrap them in a single parent or a Fragment (<>...). React requires one root element per return.

Export default

Each component file exports the component so it can be imported elsewhere. export default App at the bottom. The name matters — you import it by that name.

Components are just functions. If you've written JavaScript, you already know how to write React components. The only new syntax is JSX, and that's a small addition. Everything else — variables, functions, conditionals, arrays — works exactly like JavaScript. That's why the JavaScript foundation matters so much: once you have it, React becomes a small addition, not a new language.

🎬 How React renders to the DOM

The connection between your component function and the pixels on screen.

Open src/main.jsx. This is the entry point — the file that tells React what to render and where:

src/main.jsx 
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';
import './index.css';

const root = createRoot(document.getElementById('root'));

root.render(



);

And index.html has the root div that React targets:

index.html 




My React App

createRoot

Finds the #root div in the HTML and tells React "this is where you mount the app." React takes over that element and controls everything inside it.

render()

Calls the App component, gets back a JSX tree, and renders it into the root div. From this point on, React owns the DOM inside #root.

StrictMode

A development-only wrapper that double-invokes components to catch bugs. Doesn't affect production. Leave it on — it's a useful safety net.

One render call

You only call root.render() once. React manages all future updates through state. This is the declarative model — you don't tell React what changed, you change state and React handles it.

The mental model that makes React click. You don't write "add this element to the DOM." You write "here's what the UI should look like given this state." When state changes, React re-runs your component function, compares the new JSX tree to the old one, and patches only the differences. That's it. That's the entire model. Once you internalize "UI = function of state," React becomes simple — and this simple model is what makes large apps manageable.

    ❓ Frequently asked questions

    How do I install React?

    The modern way is Vite. Run three commands: npm create vite@latest my-app -- --template react, then cd my-app, then npm install. After that, npm run dev starts a dev server at localhost:5173. That's the entire setup.

    What is JSX and why does React use it?

    JSX is a syntax extension that lets you write HTML-like code inside JavaScript. It's not valid JavaScript — it's compiled by Vite into React.createElement calls at build time. React uses it because it's more readable than raw function calls.

    What is the difference between className and class in React?

    In HTML you write class='button'. In JSX you write className='button'. This is because class is a reserved keyword in JavaScript. Same for htmlFor instead of for on labels.

    How does a React component render to the DOM?

    In main.jsx, you call createRoot(document.getElementById('root')).render(). React takes the App component, calls its function, gets back a tree of React elements, and efficiently updates the DOM inside the root element.

    What is the difference between a component and a regular function?

    A React component is a function that returns JSX. It starts with a capital letter. It can accept props. It can use hooks. A regular function can do none of those things.

    Do I need to know JSX before React?

    No — you learn JSX as part of React. JSX is small. What you DO need to know before React is JavaScript itself — functions, arrays, objects, arrow functions, and destructuring.

    Why do components start with a capital letter?

    React uses the case to distinguish components from HTML elements.

    is an HTML element. is a React component. Lowercase components silently fail to render.

    What is a self-closing tag in JSX?

    In JSX, ALL tags must be closed — either with an explicit closing tag or as self-closing. Writing

    without a closing tag is a syntax error. This is the #1 difference from HTML.
