Why TypeScript

JavaScript is flexible — a variable can hold anything, and you only find out it's the wrong type when your code crashes in production. TypeScript adds a type layer on top. You declare what types exist, the compiler checks every assignment against them, and errors surface in your editor before you ever run the code. It's not a new language — it's JavaScript with a seatbelt.

The payoff compounds as codebases grow. A 10-line script doesn't need types. A 10,000-line app with 50 developers does — and that's why every major framework (Angular, NestJS, Deno) and most modern React teams use TypeScript by default. TypeScript's autocomplete alone is worth it: rename a function, and your editor instantly shows every call site. Miss an argument, and you see a red underline before saving.

Microsoft created TypeScript in 2012. It's now the standard for serious JavaScript projects. And unlike learning a second language, you don't start from zero — you already know 90% of it if you know JavaScript.

🎯 The 5 concepts that matter most

If you only truly understand five things about TypeScript, make it these.

1. Types are erased at runtime

TypeScript compiles to JavaScript by stripping all types. Types cost zero bytes and zero milliseconds at runtime. They exist only in your editor and during the compile step — they catch bugs before the code ships.

2. Inference beats annotation

TypeScript infers most types for you. You rarely need to annotate variables — let let x = 5 infer number. Annotate function parameters, return values, and exported APIs. Over-annotating is a beginner habit; the compiler is good at this.

3. Unions + narrowing = safety

A union says "one of these." Narrowing refines it based on runtime checks. Together they model real states: 'loading' | 'success' | 'error', or string | null. This pair is why TypeScript handles dynamic data gracefully.

4. Generics preserve type info

A generic () is a type variable. It lets you write one function that works with any type while keeping the type information flowing through. Without generics, reusable code has to fall back to any — and lose all safety.

5. Structural typing, not nominal

TypeScript checks shapes, not names. If two interfaces have the same properties, they're compatible. This is duck typing with compile-time checking — and it means you can pass a { name: 'x' } object anywhere { name: string } is expected.

⚠️ Common mistakes (from real beginners)

Each of these will cost you hours if you don't know it.

1. Learning TypeScript before JavaScript

The #1 reason beginners struggle. TS is a layer on JS — if you don't understand JS first, TS errors feel like noise. Complete the JavaScript track first.

2. Reaching for any

any disables type checking entirely — you've turned TS off. When you're stuck, use unknown and narrow it. Reserve any for actual interop with untyped libraries.

3. Over-annotating variables

const x: number = 5 is noise. The compiler infers number. Annotate parameters, return types, and exported APIs — let the rest be inferred.

4. Confusing interface and type

Both describe shapes, but only interface supports declaration merging. Use interface for public object shapes you might extend; use type for unions, intersections, and aliases.

5. Forgetting that types are erased

if (typeof x === 'string') works because it's real runtime code. if (x is string) is a type guard — it disappears at runtime. Never write type-only logic that needs to run.

6. Non-null assertion everywhere

value! tells TS "trust me, it's not null." If it IS null, you crash at runtime. Narrow with checks instead of asserting.

7. Fighting the compiler instead of learning from it

When TS complains, it's usually right. Read the error — it points to the exact line and explains the mismatch. Beginners add as any; intermediates fix the actual type.

8. Skipping tsconfig

Default tsconfig.json is permissive. Turn on strict: true from day one — it catches null/undefined bugs, implicit any, and more. Retrofitting strict later is painful.

❓ Frequently asked questions

Do I need to know JavaScript before TypeScript?

Yes — absolutely. TypeScript is JavaScript with types bolted on. Every line of TypeScript is valid JavaScript once the types are stripped. If you don't understand functions, arrays, objects, arrow functions, closures, and promises, learning TypeScript becomes memorization. Spend 2-3 months on JavaScript first.

What is TypeScript?

TypeScript is a superset of JavaScript developed by Microsoft. It adds optional static types to JavaScript. You write TypeScript, the compiler strips the types and outputs plain JavaScript that runs in any browser or Node.js. The types are checked at build time — they catch bugs before your code runs.

What is the difference between TypeScript and JavaScript?

JavaScript is dynamically typed — variables can hold anything, type errors appear at runtime. TypeScript is statically typed — you declare what types variables, parameters, and return values have, and the compiler catches type errors before the code runs. TypeScript is a superset: every valid JavaScript file is also valid TypeScript.

What is a type annotation?

A type annotation is a label you attach to a variable, parameter, or return value to tell TypeScript what type it should hold. Example: let name: string = 'Alice'; the : string is the annotation. TypeScript then enforces that name is always a string — assigning a number is a compile error.

What is the difference between interface and type?

Both describe object shapes. interface is designed for object shapes and can be extended with 'extends' and merged (declaration merging). type is more flexible — it can describe unions, intersections, tuples, primitives, and conditional types. Use interface for object shapes you might extend, type for everything else.

What are generics in TypeScript?

Generics let you write functions and components that work with any type while preserving type information. function identity(x: T): T { return x; } — T is a type parameter filled in by the caller. Generics are how you write reusable, type-safe code — the type is a variable for types.

What is type narrowing?

Narrowing is how TypeScript refines a broad type into a specific one based on runtime checks. If you have a value of type string | number, doing typeof value === 'string' inside an if narrows the type to string inside the block. TypeScript understands typeof, instanceof, in, Array.isArray, discriminated unions, and custom type guards.

Do I need a build tool to use TypeScript?

Technically you can use the TypeScript Playground or compile with tsc in the terminal. For real projects, use Vite or Next.js with the TypeScript template. Vite handles TS compilation, hot reload, and type checking. Just install typescript locally and let Vite do the rest.
