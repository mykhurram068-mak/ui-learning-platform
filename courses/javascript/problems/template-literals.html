Template literals.
Backticks, ${'{}'}

They preserve line breaks, and they can be "tagged" with a function for advanced processing. If you're still concatenating strings with +, template literals are simpler and less error-prone. This page covers the syntax, the differences from quotes, and the tagged-template pattern that powers styled-components and GraphQL.

Short answer: Use backticks for any string with a variable or a newline. Hello, ${'${name}'} instead of 'Hello, ' + name. Multi-line strings just work — no \n escapes needed. Expression interpolation accepts any JS: ${'${a + b}'}, ${'${user.active ? "yes" : "no"}'}. Tagged templates (fn`...`) let a function process the template — rare in app code, common in libraries. Use backticks by default for anything non-trivial; use quotes for plain literal strings.

✅ The three differences from quotes

Why backticks are the default in modern JavaScript.

Interpolation

Hi, ${'${name}'} — embed any expression. Quotes need + concatenation.

Multi-line

Backticks preserve line breaks. Quotes need \n or concatenation.

Tagged templates

fn`...` — a function processes the template. Only backticks support this.

No escaping

Backticks don't need escaped quotes. You can use " and ' freely inside.

✅ Before and after

The same strings, quotes vs backticks.

interpolation.js 
const name = 'Alice';
const age = 30;
const role = 'admin';

// ❌ Concatenation with quotes
const a = 'Hello, ' + name + '!';
const b = 'Name: ' + name + ', Age: ' + age;
const c = role === 'admin' ? 'Admin access' : 'Limited access';
const d = "Status: " + (age >= 18 ? 'adult' : 'minor');

// ✅ Template literals
const a2 = `Hello, ${name}!`;
const b2 = `Name: ${name}, Age: ${age}`;
const c2 = `${role === 'admin' ? 'Admin access' : 'Limited access'}`;
const d2 = `Status: ${age >= 18 ? 'adult' : 'minor'}`;

console.log(a); console.log(a2);
console.log(b); console.log(b2);
console.log(c); console.log(c2);
console.log(d); console.log(d2);

// Output is identical — only the syntax differs.
Output:
Hello, Alice!
Hello, Alice!
Name: Alice, Age: 30
Name: Alice, Age: 30
Admin access
Admin access
Status: adult
Status: adult

Why template literals are better:

1. No quote escaping
❌ "It's " + user + "'s turn"
✅ `It's ${user}'s turn`

2. No + operators between parts
❌ 'Hello, ' + name + ', you are ' + age
✅ `Hello, ${name}, you are ${age}`

3. Ternaries fit naturally
❌ 'Status: ' + (active ? 'on' : 'off')
✅ `Status: ${active ? 'on' : 'off'}`

4. Fewer bugs
Concatenation with numbers is easy to get wrong:
❌ 'Total: ' + a + b // 'Total: 12' (a=1, b=2, not 3)
✅ `Total: ${a + b}` // 'Total: 3'

5. Expressions, not just variables
✅ `${a + b}`, `${user?.name}`, `${items.length}`
Any expression works.

✅ Multi-line strings

Backticks preserve newlines.

multiline.js 
// ❌ Without backticks — escape newlines
const email1 =
'Dear ' + name + ',\n\n' +
'Thank you for your order.\n' +
'Your total is $' + total + '.\n\n' +
'Best regards,\n' +
'The Team';

// ✅ With backticks — natural line breaks
const email2 = `Dear ${name},

Thank you for your order.
Your total is $${total}.

Best regards,
The Team`;

console.log(email2);
The output is the same.
The difference is the source code.

With backticks:
→ Lines break naturally
→ Variables interpolate with ${}
→ No escaping needed
→ The code looks like the output

✅ Tagged templates

A function that processes the template.

tagged.js 
function tag(strings, ...values) {
  return strings.reduce((result, str, i) => {
    return result + str + (values[i] ?? '');
  }, '');
}

const name = 'Alice';
const age = 30;

tag`Hello, ${name}. You are ${age}.`;
The function receives:
strings: the static parts as an array
values: the interpolated expressions

Used in:
✅ styled-components
✅ GraphQL (gql tag)
✅ lit-html

Don't use ${'{a}'}${'{b}'} when you mean ${'{a + b}'}. This is the most common template-literal bug. `${a}${b}` concatenates the string forms of a and b. If a = 1 and b = 2, the result is "12" instead of "3". When you want arithmetic, put both operands inside one wrapper: `${a + b}`.

⚠️ Common mistakes

The template-literal mistakes that cost real time.

1. Forgetting the backtick

Using standard quotes leaves your syntax literal instead of evaluated.

2. Concatenation errors

Using side-by-side components instead of completing operations inline inside single parameter closures.

3. Hidden indentation metrics

Multi-line strings explicitly capture source code indentation spacing into the live template string value output.

❓ Frequently asked

What are template literals?

Template literals are modern string wrappers using backticks that support robust expressions and multiline formatting natively.

How do they perform?

Performance matches old string configurations across layout engines. Optimize for readability first.
