Template literals.
Backticks, {'{}'}, they preserve line breaks, and they can be "tagged" with a function for advanced processing. If you're still concatenating strings with +, template literals are simpler and less error-prone. This page covers the syntax, the differences from quotes, and the tagged-template pattern that powers styled-components and GraphQL.

Short answer: Use backticks for any string with a variable or a newline. Hello, ${'${name}'} instead of 'Hello, ' + name. Multi-line strings just work — no \n escapes needed. Expression interpolation accepts any JS: latex {' {a + b}'}, latex {' {user.active ? "yes" : "no"}'}. Tagged templates (fn...) let a function process the template — rare in app code, common in libraries. Use backticks by default for anything non-trivial; use quotes for plain literal strings.

✅ The three differences from quotes

Why backticks are the default in modern JavaScript.

Interpolation

Hi, ${'${name}'} — embed any expression. Quotes need + concatenation.

Multi-line

Backticks preserve line breaks. Quotes need \n or concatenation.

Tagged templates

fn... — a function processes the template. Only backticks support this.

No escaping

Backticks don't need escaped quotes. You can use " and ' freely inside.

✅ Before and after

The same strings, quotes vs backticks.

interpolation.js

Why template literals are better:

1. No quote escaping
❌ "It's " + user + "'s turn"
✅ It's ${user}'s turn`

2. No + operators between parts
❌ 'Hello, ' + name + ', you are ' + age
✅ Hello,${name}, you are ${age}

3. Ternaries fit naturally
❌ 'Status: ' + (active ? 'on' : 'off')
✅ Status:${active ? 'on' : 'off'}`

4. Fewer bugs
Concatenation with numbers is easy to get wrong:
❌ 'Total: ' + a + b // 'Total: 12' (a=1, b=2, not 3)
✅ Total: ${a + b}` // 'Total: 3'

5. Expressions, not just variables
✅ ${a + b}`, `$`{user?.name}`,${items.length}`
Any expression works.

The one thing to watch:
${a}${b} is string concatenation.
${a + b}` is arithmetic, then string.
Different results. Be intentional.

✅ Tagged templates

A function that processes the template.

tagged.js 
// Tagged template — the function receives
// the static parts and the dynamic values
function tag(strings, ...values) {
console.log(strings);
console.log(values);
return strings.reduce((result, str, i) => {
return result + str + (values[i] ?? '');
}, '');
}

const name = 'Alice';
const age = 30;

tagHello,${name}. You are ${age}.;

// strings: ['Hello, ', '. You are ', '.']
// values: ['Alice', 30]
// returns: 'Hello, Alice. You are 30.'

// The function can transform values
function upper(strings, ...values) {
return strings.reduce((result, str, i) => {
return result + str + String(values[i] ?? '').toUpperCase();
}, '');
}

console.log(upperHi${name}, you are ${age});
// "Hi ALICE, you are 30"
Tagged template anatomy:

tagHello,${name}.`

1. tag is a function.
2. The template is passed to it.
3. The function receives:
strings: the static parts as an array
values: the interpolated expressions
4. The function returns whatever it wants
— usually a string, but it could be
an object, an array, a React element,
a parsed AST.

Real-world uses:

✅ styled-components
styled.divcolor: red; padding: ${padding}`
→ returns a React component

✅ GraphQL (gql tag)
gqlquery { user { name } }
→ returns a query AST

✅ lit-html
html`
→ returns a TemplateResult

✅ SQL query builders (sql-template-strings)
sqlSELECT * FROM users WHERE id = ${id}`
→ returns a parameterized query object

Why use tagged templates:

→ The function gets the raw template parts
AND the values separately, so it can
escape, validate, or transform each.
→ This is how SQL injection is prevented:
the values never get concatenated into
the query string — they're passed as
parameters.
→ It's how libraries like styled-components
parse CSS safely.

For app code, you almost never write a tag yourself.
You use ones from libraries. But knowing what
they are makes the library's behavior less magical.

Do template literals affect performance?

Not meaningfully. Template literals are parsed once and evaluate to a string, just like concatenation. In micro-benchmarks, template literals can be slightly faster. But the difference is in nanoseconds. Choose based on readability. Hello,${name}` is clearer than 'Hello, ' + name.
