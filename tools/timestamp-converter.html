🧠 How Unix Timestamps Work

  1. Epoch start: January 1, 1970, 00:00:00 UTC — the reference point for all Unix time.
  2. Seconds: A 10-digit timestamp counts seconds since the epoch. `1706745600` = Feb 1, 2024.
  3. Milliseconds: A 13-digit timestamp counts milliseconds (× 1000). JavaScript uses these by default.
  4. Timezone-free: A Unix timestamp is the same number everywhere in the world — only the human-readable display changes.
  5. Year 2038: 32-bit systems will overflow on Jan 19, 2038. Modern 64-bit systems are safe for billions of years.

Tip: In JavaScript, use Date.now() for milliseconds or Math.floor(Date.now() / 1000) for seconds. In Python: import time; time.time().

❓ Frequently Asked Questions

What is a Unix timestamp?

A Unix timestamp (also called epoch time) is the number of seconds that have passed since January 1, 1970, 00:00:00 UTC. It is a universal way to represent time that is the same worldwide, regardless of timezone.

What is the difference between seconds and milliseconds?

A 10-digit Unix timestamp is in seconds. A 13-digit timestamp is in milliseconds (1 second = 1000 milliseconds). JavaScript uses milliseconds by default. This converter auto-detects which one you enter.

Why does Unix time start in 1970?

January 1, 1970 was chosen as the Unix epoch when the Unix operating system was being developed at Bell Labs. It was a convenient recent date that fits within 32-bit integer storage.

What is the Year 2038 problem?

On January 19, 2038, 32-bit signed integers used by older systems will overflow, causing timestamps to wrap around to 1901. Modern 64-bit systems will not be affected.

Is my data stored anywhere?

No. Everything runs locally in your browser. No timestamps are sent anywhere. No tracking, no ads.
